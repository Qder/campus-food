**课题名称：** 校园美食智能推荐与社交平台  
**依据文件：** 《（课程设计要求）校园美食智能推荐与社交平台》

---

## 一、课题名称

校园美食智能推荐与社交平台

## 二、设计目的与意义

为大学生提供一个集校园周边及食堂美食信息整合、个性化推荐、社交互动于一体的综合性平台。通过结合 SMM 框架、NoSQL、Redis、Spring Cloud 及 AI 技术，满足大学生对美食探索、分享和社交的需求，打造便捷、有趣的校园美食社交生态圈。

## 三、设计任务

完成 Web 端校园美食智能推荐与社交平台的需求分析、架构设计、数据库设计、后端实现、联调测试与设计说明书撰写。平台须同时服务普通用户、商家用户与平台管理员三类角色，覆盖用户、美食、社交、商家、订单与管理等模块，并按第七节技术要求落地微服务、缓存、容错与智能推荐。

## 四、用户需求

### 4.1 普通用户

1. **注册登录：** 支持手机号、邮箱或第三方账号（如微信、QQ）注册登录，方便快捷地进入平台。  
2. **美食浏览：** 能够按校园区域（如不同食堂、周边商圈）、美食类型（中餐、西餐、小吃等）分类浏览美食信息，包括美食图片、名称、价格、店铺位置、用户评分等。  
3. **美食搜索：** 提供关键词搜索功能，可根据美食名称、店铺名称快速查找感兴趣的美食。  
4. **个性化推荐：** 基于用户的浏览历史、评价记录、收藏偏好，以及 AI 视觉识别算法对用户上传美食图片的分析，接收个性化的美食推荐。  
5. **美食评价与分享：** 可以对品尝过的美食进行评分、撰写文字评价并上传图片，同时将喜欢的美食分享到第三方社交平台，吸引更多同学关注。  
6. **社交互动：** 查看其他用户的个人资料和美食动态，添加好友，发起私聊、群聊，围绕美食话题进行交流；参与拼单约饭活动，与志同道合的同学一起享受美食。  
7. **收藏与提醒：** 收藏感兴趣的美食和店铺，设置提醒功能，如店铺优惠活动提醒、好友美食动态提醒。

### 4.2 商家用户

1. **入驻申请：** 填写店铺基本信息（名称、地址、联系方式、营业执照等），提交入驻申请，等待平台审核。  
2. **美食管理：** 上传、编辑、下架美食信息，包括图片、名称、价格、描述、库存等；设置特色推荐菜品，展示店铺优势。  
3. **订单管理：** 接收、处理用户的订单，查看订单详情、状态（已下单、已接单、已完成、已取消），进行订单配送或自提操作。  
4. **评价回复：** 查看用户对店铺美食的评价，及时回复用户反馈，维护良好的店铺形象。  
5. **营销活动：** 发布优惠活动（如打折、满减、团购），吸引用户消费；查看活动效果数据，调整营销策略。

### 4.3 平台管理员

1. **用户管理：** 审核用户注册信息，处理违规用户账号（如恶意评价、发布不良信息），封禁或限制其使用权限。  
2. **商家管理：** 审核商家入驻申请，对已入驻商家进行资质审查和日常监督；处理商家违规行为，如虚假宣传、食品安全问题，采取警告、下架商品、取消入驻资格等措施。  
3. **内容管理：** 审核用户发布的美食评价、图片和动态，过滤违规内容；管理平台公告、活动推荐等信息的发布和展示。  
4. **数据统计与分析：** 统计平台用户数量、活跃度、订单量、交易额等数据；分析用户行为数据（如浏览偏好、消费习惯）和商家经营数据（如销量、评价情况），为平台运营决策提供依据。  
5. **系统维护：** 监控平台服务器运行状态，进行系统升级、备份和安全防护；处理系统故障和用户反馈的技术问题。

## 五、功能需求

### 5.1 用户模块

1. **注册登录功能：** 实现多种注册登录方式，验证用户信息的真实性和唯一性；记录用户登录状态，支持自动登录和退出登录操作。  
2. **个人资料管理功能：** 用户可编辑个人信息（头像、昵称、性别、所在学校、专业等），设置隐私权限（如是否公开个人动态、是否允许陌生人添加好友）。  
3. **收藏与提醒功能：** 提供美食和店铺收藏夹，方便用户快速查看感兴趣的内容；支持设置各类提醒，通过站内消息、短信或推送通知及时告知用户。

### 5.2 美食模块

1. **美食展示功能：** 按分类展示美食信息，提供图片轮播、详情页查看功能，展示美食的详细介绍、用户评分、评价数量、店铺地址和联系方式。  
2. **美食搜索功能：** 支持模糊搜索和精准搜索，根据用户输入的关键词，快速筛选出相关美食，并展示搜索结果列表。  
3. **个性化推荐功能：** 利用 AI 算法分析用户数据，生成个性化美食推荐列表，在首页或专属推荐页面展示。  
4. **美食评价功能：** 用户可提交评分（1–5 星）、文字评价和图片，系统对评价进行审核和展示；支持其他用户对评价进行点赞、回复操作。

### 5.3 社交模块

1. **好友管理功能：** 用户可搜索、添加好友，查看好友列表和好友动态；支持删除好友、拉黑用户操作。  
2. **聊天功能：** 实现一对一私聊和群聊功能，支持文字、图片、表情发送；保存聊天记录，方便用户随时查看。  
3. **拼单约饭功能：** 用户发布拼单约饭活动，设置时间、地点、美食类型等信息；其他用户可报名参加活动，活动发起者可管理参与人员名单，活动结束后可进行评价和反馈。

### 5.4 商家模块

1. **入驻审核功能：** 商家提交入驻申请后，平台管理员进行资质审核，审核通过后商家获得入驻资格，可开始管理店铺和商品。  
2. **商品管理功能：** 商家可对美食商品进行全生命周期管理，包括上架、编辑、下架、库存调整等操作；设置商品推荐标签，提升曝光率。  
3. **订单管理功能：** 实时接收用户订单，处理订单状态变更；查看订单统计数据，如按时间、菜品分类统计销量。  
4. **营销活动管理功能：** 商家创建、编辑、删除优惠活动，设置活动规则和时间；查看活动参与人数、销售额等数据，评估活动效果。

### 5.5 管理模块

1. **用户管理功能：** 管理员可查看所有用户信息，对违规用户进行处罚；统计用户活跃度、留存率等数据，分析用户行为趋势。  
2. **商家管理功能：** 审核商家入驻申请，监督商家经营行为；处理商家与用户之间的纠纷，维护平台交易秩序。  
3. **内容管理功能：** 审核用户生成内容和商家发布信息，删除违规内容；管理平台公告、推荐位，确保信息的准确性和及时性。  
4. **数据统计与分析功能：** 对平台各类数据进行汇总和分析，生成可视化报表（如柱状图、折线图、饼图）；提供数据导出功能，方便进一步分析和决策。  
5. **系统维护功能：** 监控服务器性能指标，进行系统备份和恢复；更新系统功能和修复漏洞，保障平台稳定运行。

## 六、非功能需求

### 6.1 性能需求

1. **响应时间：** 页面加载时间不超过 3 秒，复杂操作（如搜索、推荐计算）响应时间不超过 5 秒，确保用户流畅使用。  
2. **数据更新及时性：** 美食信息、用户评价、订单状态等数据实时更新，确保用户获取最新内容。

### 6.2 安全性需求

1. **用户信息安全：** 采用加密技术（如 SSL/TLS）传输用户注册登录信息，对用户密码进行哈希加密存储，防止信息泄露。  
2. **交易安全：** 集成安全可靠的支付接口，保障用户支付过程中的资金安全；对交易数据进行加密处理和备份，防止数据篡改和丢失。  
3. **系统安全：** 定期进行安全漏洞扫描和修复，防止 SQL 注入、XSS 攻击等网络安全威胁；设置防火墙，限制非法访问。

### 6.3 可用性需求

1. **界面友好性：** 设计简洁、美观、易用的界面，符合大学生审美和操作习惯；提供清晰的导航和操作指引，方便用户快速找到所需功能。  
2. **兼容性：** 开发 Web 端应用，确保各平台功能和界面的一致性和兼容性。  
3. **容错性：** 系统具备良好的容错能力，出现错误时及时提示用户，并提供合理的解决方案；自动保存用户操作进度，防止数据丢失。

### 6.4 可扩展性需求

1. **功能扩展：** 平台架构设计应便于新增功能模块，如后续可添加外卖配送功能、美食直播功能等。  
2. **数据扩展：** 随着用户和商家数量的增加，数据库能够方便地进行水平扩展和垂直扩展，以满足数据存储和处理需求。  
3. **技术扩展：** 支持引入新的技术和算法，如更先进的 AI 推荐算法、图像识别技术，提升平台性能和用户体验。

## 七、业务流程

### 7.1 用户注册登录流程

1. 用户打开平台，选择注册或登录方式（手机号、邮箱、第三方账号）。  
2. 若选择注册，填写相关信息并提交，系统验证信息有效性，发送验证码（手机号或邮箱），用户输入验证码完成注册。  
3. 若选择登录，输入账号和密码（或使用第三方账号授权登录），系统验证通过后进入平台首页。

### 7.2 美食浏览与搜索流程

1. 用户进入平台后，可在首页浏览推荐美食，或通过分类导航（区域、类型）查看美食列表。  
2. 用户在搜索框输入关键词，点击搜索按钮，系统在数据库中查询相关美食信息，返回搜索结果列表，用户点击列表项查看美食详情。

### 7.3 美食评价与分享流程

1. 用户在美食详情页点击“评价”按钮，进入评价页面，填写评分、文字评价和上传图片，提交评价。  
2. 系统审核评价内容，通过后展示在美食评价区；用户可在评价区对其他用户的评价进行点赞、回复。  
3. 用户在美食详情页或个人动态页，点击“分享”按钮，选择分享平台（微信、QQ、微博等），将美食信息分享出去。

### 7.4 社交互动流程

1. 用户在个人中心或美食动态页，点击用户头像进入对方个人资料页，选择“添加好友”，发送好友申请。  
2. 对方收到好友申请后，选择同意或拒绝；双方成为好友后，可在聊天界面发起私聊或创建群聊，进行文字、图片交流。  
3. 用户在社交模块或美食详情页，点击“拼单约饭”按钮，填写活动信息并发布；其他用户查看活动详情后，点击“报名”参加活动，活动发起者管理参与人员，活动结束后进行评价。

### 7.5 商家入驻与商品管理流程

1. 商家在平台商家入驻页面，填写店铺信息和资质证明，提交入驻申请。  
2. 平台管理员审核申请，通过后商家获得入驻权限，登录商家后台。  
3. 商家在后台添加美食商品，填写商品信息、上传图片，设置价格、库存等；对已上架商品进行编辑、下架操作，管理商品推荐标签。

### 7.6 订单管理流程

1. 用户在美食详情页或购物车页面，点击“下单”按钮，选择支付方式完成支付，生成订单。  
2. 商家在后台收到订单通知，查看订单详情，选择接单或取消订单；接单后进行备货、配送或通知用户自提，更新订单状态。  
3. 用户在个人中心查看订单状态，订单完成后可对商家和美食进行评价。

### 7.7 平台管理流程

1. 管理员登录平台管理后台，查看用户列表，对违规用户进行封禁、限制操作；审核商家入驻申请，处理商家违规行为。  
2. 管理员管理平台内容，审核用户发布的评价、动态和商家发布的信息，删除违规内容；发布平台公告、设置推荐位。  
3. 管理员在数据统计模块查看各类数据报表，分析平台运营情况，根据数据调整平台策略；监控系统运行状态，进行系统维护和升级。

## 八、数据需求

### 8.1 数据实体

1. **用户：** 用户 ID、手机号、邮箱、第三方账号 ID、昵称、头像、性别、所在学校、专业、注册时间、登录时间、密码哈希值等。  
2. **商家：** 商家 ID、店铺名称、地址、联系方式、营业执照图片、入驻时间、审核状态、管理员备注等。  
3. **美食：** 美食 ID、商家 ID、美食名称、类型、价格、库存、描述、图片、评分、评价数量、推荐标签等。  
4. **订单：** 订单 ID、用户 ID、商家 ID、美食 ID、订单金额、订单状态、下单时间、支付时间、完成时间、配送方式等。  
5. **评价：** 评价 ID、用户 ID、美食 ID、评分、评价内容、评价图片、评价时间等。  
6. **好友关系：** 关系 ID、用户 ID1、用户 ID2、添加时间、备注等。  
7. **聊天记录：** 记录 ID、聊天双方 ID、消息内容、消息类型（文字、图片、表情）、发送时间等。  
8. **拼单约饭活动：** 活动 ID、发起者 ID、活动名称、时间、地点、美食类型、参与人数限制、活动状态、报名截止时间等。

### 8.2 数据关系

1. **用户与美食：** 多对多。一个用户可评价多个美食，一个美食可被多个用户评价；用户可收藏多个美食，一个美食可被多个用户收藏。  
2. **用户与商家：** 多对多。一个用户可在多个商家消费，一个商家可为多个用户提供服务；用户可关注多个商家，一个商家可被多个用户关注。  
3. **用户与订单：** 一对多。一个用户可生成多个订单，一个订单对应一个用户。  
4. **商家与美食：** 一对多。一个商家可提供多个美食，一个美食属于一个商家。  
5. **商家与订单：** 一对多。一个商家可接收多个订单，一个订单对应一个商家。  
6. **用户与好友关系：** 多对多。一个用户可与多个用户建立好友关系，一个好友关系涉及两个用户。  
7. **用户与聊天记录：** 多对多。一个用户参与多个聊天会话，一个聊天会话包含多个用户的聊天记录。  
8. **用户与拼单约饭活动：** 多对多。一个用户可发起或参加多个活动，一个活动可由多个用户参与。

## 九、技术要求（必须落实）

### 9.1 整体架构

采用 Spring Cloud 搭建微服务架构，将平台拆分为**用户服务、美食服务、社交服务、商家服务、订单服务**等多个独立的微服务模块。每个微服务负责特定的功能，通过 **Eureka** 实现服务注册与发现，使得各个微服务能够相互感知并进行通信，降低系统耦合度，提高系统的可维护性和扩展性。

### 9.2 服务调用与管理

1. **Ribbon：** 实现客户端负载均衡。当多个微服务实例提供相同功能时，Ribbon 能够智能地将请求分配到不同的服务实例上，避免单个服务压力过大，保证系统的高可用性。例如，用户访问美食服务获取美食信息时，Ribbon 根据负载情况选择合适的美食服务实例处理请求。  
2. **Feign：** 实现声明式服务调用，简化微服务之间的调用过程。开发人员只需通过定义接口和注解，即可实现对其他微服务的调用，无需编写复杂的 HTTP 请求代码。例如，社交服务在获取用户信息时，可通过 Feign 直接调用用户服务的接口获取数据。  
3. **Hystrix：** 实现服务容错保护。当某个微服务出现故障或响应超时，Hystrix 自动熔断，防止故障扩散，并提供 fallback 机制返回默认数据或友好提示，保证系统稳定性。例如，若订单服务出现问题，Hystrix 及时熔断，避免影响用户浏览美食等其他功能。

### 9.3 Redis 技术应用

使用 Redis 缓存：

- 热门美食信息；  
- 用户频繁搜索的美食结果；  
- 用户的浏览历史记录。

当用户再次访问平台时，系统可以直接从 Redis 缓存中读取数据，快速展示美食内容，减少对 **MongoDB** 数据库的访问压力，显著提升页面加载速度和用户体验。

### 9.4 AI 技术应用

1. **个性化推荐（必做）：** 运用**协同过滤算法**，分析用户的历史浏览记录、评价数据以及与其他用户的行为相似性，挖掘用户的美食偏好，为用户生成个性化的美食推荐列表。同时，结合**深度学习推荐模型**（如基于神经网络的推荐算法），对用户和美食的多维度特征进行深度分析，进一步提升推荐的准确性和多样性，使推荐结果更符合用户的实际需求。  
2. **AI 视觉识别（可选项）：** 对用户上传的美食图片进行分析，提取图片中的菜品特征、色彩信息等，结合美食数据库中的信息，自动识别美食种类、推荐相似美食或关联的店铺，为用户提供更直观、智能的美食探索方式。
