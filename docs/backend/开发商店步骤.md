开发“商家模块”时，我建议你采用先跑通一个完整功能，再逐步扩展的方式。不要一上来就把商品、订单、营销活动全部开发完，这样更容易理解每一层代码的作用，也方便你自己实现和调试。

结合你上传的《校园美食智能推荐与社交平台》课程设计要求，商家模块主要包括入驻审核、商品管理、订单管理和营销活动管理。

## 一、商家模块开发步骤

## 1

梳理商店业务需求

- 明确商店与商家的关系：一个商家可以管理自己的店铺。
- 确定店铺需要的字段：店铺 ID、名称、地址、联系方式、简介、封面、营业状态、审核状态、创建时间。
- 明确角色权限：普通用户查看店铺，商家管理自己的店铺，管理员审核店铺。

## 2

设计数据库

- 确定店铺表及字段类型。
- 确定主键、外键或关联字段。
- 设计商家与店铺的关联关系。
- 确定审核状态、营业状态的取值。
- 编写建表 SQL 或数据库迁移脚本。

## 3

规划后端代码结构

按照项目现有架构，先确定各层职责与文件位置：

- `entity`：店铺实体。
- `mapper`：数据库访问。
- `service`：店铺业务逻辑。
- `controller`：接收和响应 HTTP 请求。
- `dto` / `vo`：接收前端参数、返回展示数据。

## 4

先实现店铺基础 CRUD

按照下面的顺序逐个完成：

1. 新增店铺。
2. 根据 ID 查询店铺详情。
3. 分页查询店铺列表。
4. 修改店铺信息。
5. 删除店铺或执行逻辑删除。
6. 查询当前商家自己的店铺。

每完成一个接口，就进行一次接口测试，不要等所有接口写完才测试。

## 5

加入店铺入驻与审核流程

- 商家提交入驻申请。
- 初始状态设为待审核。
- 管理员查看待审核列表。
- 管理员通过或驳回申请。
- 审核通过后，店铺才能正常展示。
- 记录驳回原因和审核信息。

## 6

补充业务规则与权限

- 普通用户只能查看允许公开的店铺。
- 商家只能修改自己有权管理的店铺。
- 未审核通过的店铺不能正常营业展示。
- 校验必填字段、联系方式、价格等输入。
- 防止通过修改请求参数越权操作其他商家的店铺。

## 7

开发前端页面

- 店铺列表页。
- 店铺详情页。
- 商家店铺管理页。
- 新增和编辑店铺表单。
- 商家入驻申请页。
- 管理员审核页。

页面完成一个，就与对应后端接口联调一个。

## 8

测试、修复与提交

- 测试新增、查询、修改、删除。
- 测试不同角色的权限。
- 测试待审核、通过、驳回等状态流转。
- 检查数据库数据是否正确。
- 运行项目测试，确认原有功能没有受到影响。
- 完成 Git 提交。

## 二、后续开发顺序

店铺基础功能完成后，再依次开发关联模块：

店铺管理

入驻、审核、信息维护

商品管理

菜品新增、上下架、价格、库存

订单管理

下单、接单、取消、完成

营销活动管理

优惠、满减、团购

## 三、你现在先做哪一步？

先完成第 1 步和第 2 步，不急着写代码。 把店铺字段、角色权限和数据库关系确定下来，再进入实体类和接口开发。

建议你每次只实现一个小任务：自己写代码 → 运行测试 → 遇到问题再分析。这样最后不仅能完成课程设计，也能真正理解项目的开发流程。
