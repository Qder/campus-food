# 私聊会话与消息笔记（campus-food）

> 对照当前代码：`social-service` 的 `POST /social/sessions`、`GET|POST /social/sessions/{sessionId}/messages`。  
> 契约：`docs/frontend/API-frontend-v1.3.md` 4.6.7 / 4.6.8。本期只做 **`sessionType=1` 私聊**。  
> 群聊表（`chat_group*`）、WebSocket、黑名单增删（4.6.9）都还没做；拉黑表只在建会话、发消息时**只读拦截**。

---

## 1. 要解决什么问题

聊天有两类数据：

| 数据 | 特点 | 放哪 |
|------|------|------|
| 会话是谁、谁在里面、最后一条预览 | 行少、要关联好友/拉黑、要事务 | MySQL `campus_food` |
| 每条消息正文 | 行多、按时间刷、主键当游标 | MongoDB `campus_food_chat.chat_message` |

MySQL 再留一张 **`chat_message_index`**：不存正文，只存「Mongo 主键 + 会话 + 发送者 + 类型 + 时间」，方便以后按会话统计、对账。当前拉历史是直接查 Mongo，索引表是发信时同步写一行。

私聊就是**两个人一场对话**。成员表设计成「一人一行」，是为了以后群聊复用同一张表；私聊建会话时只会插 **两行**，不会变成多人会话。

## 2. 库怎么准备

### 2.1 MySQL

库名与 `social-service` 的数据源一致：`campus_food`（`social-service/src/main/resources/application.yml`）。

表定义在仓库根目录 **`建表语句.sql` 第 6 节**（好友 / 私聊元数据 / 群聊）。聊天用到的表：

- 已有、本期要读写：`chat_session`、`chat_session_member`、`chat_message_index`
- 已有、本期只读：`friendship`（须已是好友）、`user_blacklist`（双向未拉黑）
- 建了但本期不用：`chat_group`、`chat_group_member`

本地若还没建过这些表，对 `campus_food` 执行该 SQL 里对应 `CREATE TABLE`（注意文件开头有 `DROP`，整文件重跑会清数据）。表结构本期**不改**，代码按现有列写。

MyBatis 驼峰：`map-underscore-to-camel-case: true`，所以列 `peer_user_id` 对应实体 `peerUserId`。

### 2.2 MongoDB

配置：

```yaml
spring:
  data:
    mongodb:
      auto-index-creation: true   # 启动时按实体 @CompoundIndex 建索引
  mongodb:
    uri: mongodb://localhost:27017/campus_food_chat
```

- 库：`campus_food_chat`（和 MySQL 的 `campus_food` 分开）
- 集合：`chat_message`（`ChatMessage` 上 `@Document(collection = "chat_message")`）
- 复合索引 `idx_session_time`：`{ sessionId: 1, createdAt: -1 }`，给「某会话按时间倒序 / 早于某时刻」用

集合一般**不用手建**：第一次 `chatMessageRepository.save` 会自动出现。本机要先装并启动 Mongo（默认 `27017`）。连通性探测是 `ChatPingController`（`/chat/ping` 一类），**业务接口不要走它**。

### 2.3 网关

`api-gateway` 已有 `Path=/social/**` → `lb://social-service`。前端打 `http://localhost:8080/social/...`，不要直连 8084。

## 3. 表与集合分别干什么

### 3.1 关系（概念）

```
user 1001 ──好友── user 1002
        \            /
         \          /
        chat_session  (一场私聊，session_type=1)
              │
              ├── chat_session_member × 2   （1001 一行、1002 一行）
              ├── chat_message_index × N    （MySQL 索引，一条消息一行）
              └── Mongo chat_message × N    （正文，_id 写回 mongo_msg_id）
```

**不要**用 `chat_session.peer_user_id` 当「这一对是否已有会话」的唯一依据：创建人眼里对方是 B，B 再点「发消息」时 `peer_user_id` 会是 A，方向反了。代码用成员表：**两人都在同一 `session_id` 且 `session_type=1`** 就算同一场私聊。

### 3.2 `chat_session`（一场对话一行）

| 列 | 含义（私聊） |
|----|----------------|
| `id` | 会话 ID，后面路径里的 `{sessionId}` |
| `session_type` | **1** 私聊；2 群聊本期拒绝 |
| `peer_user_id` | 创建人写入的对方 ID，**冗余**；查找已有会话不靠它 |
| `group_id` | 私聊为 `NULL` |
| `last_msg_preview` | 列表预览：文字截断，或 `[图片]` |
| `last_msg_at` | 最后一条发送时间 |
| `created_at` / `updated_at` | 建会话 / 行更新时间 |

建会话时只插 `session_type`、`peer_user_id`（`group_id` 空）。发消息成功后再 `UPDATE` 预览和时间。

### 3.3 `chat_session_member`（谁在这场对话里）

| 列 | 含义 |
|----|------|
| `session_id` + `user_id` | 唯一键 `uk_csm`，同一人不能进同一会话两次 |
| `unread_count` | **这个人**的未读；建会话写 `0`。发信加一、已读清零**还没做** |
| `joined_at` | 加入时间，默认 `CURRENT_TIMESTAMP` |

私聊：`INSERT` 两次，当前用户一行、对方一行。  
拉历史 / 发消息：先 `countMember(sessionId, 当前用户)`，不是成员就「无权访问该会话」。

### 3.4 `chat_message_index`（MySQL 侧消息索引）

| 列 | 含义 |
|----|------|
| `mongo_msg_id` | Mongo `_id` 的字符串，唯一键 `uk_mongo_msg` |
| `session_id` | 哪一场 |
| `from_user_id` | 谁发的 |
| `msg_type` | `TEXT` / `IMAGE` / `EMOJI` |
| `created_at` | 发送时间，与 Mongo 文档同一时刻 |

**没有 `content`。** 正文只在 Mongo。

### 3.5 Mongo `chat_message`（正文）

实体 `ChatMessage` 字段：

| 字段 | 含义 |
|------|------|
| `id`（`_id`） | 对外 `msgId`，**字符串**（文档示例里的数字 90001 以字符串为准） |
| `sessionId` | 对应 MySQL `chat_session.id` |
| `fromUserId` | 发送者 |
| `msgType` | `TEXT` / `IMAGE` / `EMOJI` |
| `content` | 文字、图片 URL、或表情码；IMAGE **不在本接口上传**，假定已是 URL |
| `clientMsgId` | 前端去重，可空 |
| `createdAt` | 发送时间 |

### 3.6 只读：`friendship`、`user_blacklist`

- `friendship`：双向各一行。`selectByUserIdAndFriendId(我, 对方) <= 0` → 「请先添加对方为好友」
- `user_blacklist(user_id, blocked_uid)`：`countPair(对方, 我)` 对方拉黑了我；`countPair(我, 对方)` 我拉黑了对方。建会话、发消息都要**双向**查。本期没有拉黑 CRUD，表里有数据仍会拦住。

用户昵称头像不在社交库：Feign `UserFeignClient` → user-service `/internal/users/{id}`。

## 4. 数字例子（两人一场）

用户 `1001` 对 `1002` 第一次点「发消息」，再发一句「明天一起去？」：

**`chat_session`**

| id | session_type | peer_user_id | last_msg_preview | last_msg_at |
|----|--------------|--------------|------------------|-------------|
| 5001 | 1 | 1002 | 明天一起去？ | 2026-10-26 19:40:00 |

**`chat_session_member`**

| session_id | user_id | unread_count |
|------------|---------|--------------|
| 5001 | 1001 | 0 |
| 5001 | 1002 | 0 |

**Mongo `chat_message`**

```json
{
  "_id": "665f2a9c1b2e4d0012ab34cd",
  "sessionId": 5001,
  "fromUserId": 1001,
  "msgType": "TEXT",
  "content": "明天一起去？",
  "clientMsgId": "c-1729939200-1",
  "createdAt": "2026-10-26T19:40:00"
}
```

**`chat_message_index`**

| mongo_msg_id | session_id | from_user_id | msg_type | created_at |
|--------------|------------|--------------|----------|------------|
| 665f2a9c1b2e4d0012ab34cd | 5001 | 1001 | TEXT | 2026-10-26 19:40:00 |

`1002` 再 `POST /social/sessions` 且 `peerUserId=1001`：成员表两边都能对上 → **返回同一个 5001**，不再 insert。

## 5. 本项目里的文件

| 文件 | 职责 |
|------|------|
| `SocialController` | `/social/sessions`、`/social/sessions/{id}/messages` |
| `SocialService` / `SocialServiceImpl` | 校验 + 写两库 |
| `ChatSession` / `ChatSessionMember` / `ChatMessageIndex` | MySQL 实体 |
| `ChatSessionMapper(.xml)` | insert、按 id 查、两人私聊、更新最后一条 |
| `ChatSessionMemberMapper(.xml)` | insert、是否成员、私聊对方 id |
| `ChatMessageIndexMapper(.xml)` | insert 索引 |
| `UserBlacklistMapper(.xml)` | `countPair` |
| `ChatMessage` + `ChatMessageRepository` | Mongo 正文与分页查询 |
| `CreateSessionDTO` / `SendMessageDTO` | 入参 |
| `ChatSessionVO` / `ChatMessageVO` / `ChatMessagePageVO` | 出参 |
| `ChatPingController` | 只探 Mongo，不是业务接口 |

常量（`SocialServiceImpl`）：`SESSION_TYPE_PRIVATE = 1`，`TEXT` 最长 1000，预览最长 255，`msgType` 只能 `TEXT`/`IMAGE`/`EMOJI`。拉历史 `size` 默认 20、最大 50。

信封与好友接口一样：直接返回 VO；失败 `BizException` → HTTP 400 `{code,message}`，**不**改成文档里的 `40301`/`40900` 数字码。

## 6. 三个接口怎么动表

都要 JWT。`requireCurUserId()` 从 `UserContext` 取当前用户，body 里不要信「我是谁」。

### 6.1 `POST /social/sessions` 创建或返回已有私聊

Body：`peerUserId`、`sessionType`（必须为 1）。

```
JwtAuthInterceptor → UserContext
SocialController.createOrGetSession
  └─ SocialServiceImpl.createOrGetSession
        ├─ sessionType != 1        → 「本期仅支持私聊」
        ├─ 自己 == 对方             → 「不能与自己发起会话」
        ├─ loadUser(peerId)        → Feign，用户不存在则失败
        ├─ friendshipMapper.selectByUserIdAndFriendId(我, 对方)
        ├─ assertNotBlocked(我, 对方, forCreate=true)
        │     countPair(对方, 我) → 「你已被对方拉黑，无法发起会话」
        │     countPair(我, 对方) → 「你已将对方拉黑，无法发起会话」
        ├─ chatSessionMapper.selectPrivateBetween(我, 对方)
        │     SQL：session_type=1 且两人各有一条 member
        │     有 → 用已有 id
        │     无 → INSERT chat_session
        │           INSERT member 我（unread=0）
        │           INSERT member 对方
        └─ toSessionVo：Feign 对方昵称、头像
```

成功 data：`sessionId, sessionType, peerUserId, peerNickname, peerAvatarUrl`。

`selectPrivateBetween` 核心 SQL：

```sql
SELECT s.*
FROM chat_session s
INNER JOIN chat_session_member a ON a.session_id = s.id AND a.user_id = #{userId}
INNER JOIN chat_session_member b ON b.session_id = s.id AND b.user_id = #{peerUserId}
WHERE s.session_type = 1
LIMIT 1
```

### 6.2 `GET /social/sessions/{sessionId}/messages` 拉历史

Query：`beforeMsgId`（Mongo `_id` 字符串，可选）、`size`。

```
requireSessionMember(sessionId, 我)
  ├─ chat_session 没有这行 → 「会话不存在」
  └─ countMember = 0      → 「无权访问该会话」

size 空或 <1 → 20；再 min(size, 50)

beforeMsgId 空
  → findBySessionIdOrderByCreatedAtDesc(sessionId, 第一页 size 条)
beforeMsgId 有
  → findById(beforeMsgId)
  → 找不到或不属于本会话 → 「消息不存在」
  → findBySessionIdAndCreatedAtBeforeOrderByCreatedAtDesc(sessionId, 该条 createdAt, size)

hasMore = 本页条数 == size
list 倒序（新的在前）；前端渲染若要正序自己反转
fromNickname：自己的消息固定「我」，对方用 Feign 昵称
```

这是**游标分页**，不是 `page/total`。没有「比这条更早」时列表变短，`hasMore=false`。

### 6.3 `POST /social/sessions/{sessionId}/messages` 发一条

Body：`msgType`、`content`、可选 `clientMsgId`。

```
requireSessionMember
selectPeerUserId（成员表里 user_id <> 我）
assertNotBlocked(..., forCreate=false)   -- 文档：每次发送前都可能被拉黑
校验类型、非空；TEXT 长度 ≤ 1000

① chatMessageRepository.save     → Mongo，得到 _id
② chatMessageIndexMapper.insert  → MySQL 索引（mongo_msg_id = ① 的 id）
③ chatSessionMapper.updateLastMessage(预览, now)

返回：msgId, clientMsgId, sessionId, msgType, content, createdAt
      （实现里还会带 fromUserId / fromNickname，多出来的字段前端可忽略）
```

顺序必须是 **先 Mongo 再索引再会话预览**。`@Transactional` 只管 MySQL；Mongo 不在同一事务里。若 ① 成功、② 失败，可能留下一条没有索引的 Mongo 文档（课设可接受）。

预览：`IMAGE` → `[图片]`；其它取 content，超过 255 截断。

IMAGE 的 `content` 假定已是上传接口返回的 URL，本模块不接文件。

## 8. 联调时怎么看库

MySQL：

```sql
SELECT * FROM chat_session WHERE id = 5001;
SELECT * FROM chat_session_member WHERE session_id = 5001;
SELECT * FROM chat_message_index WHERE session_id = 5001 ORDER BY created_at DESC;
SELECT * FROM friendship WHERE user_id = 1001 AND friend_id = 1002;
SELECT * FROM user_blacklist WHERE user_id = 1002 AND blocked_uid = 1001;
```

Mongo（mongo shell / Compass，库 `campus_food_chat`）：

```javascript
db.chat_message.find({ sessionId: NumberLong(5001) }).sort({ createdAt: -1 })
```

前端：登录拿到 JWT → 两人先互为好友 → `POST /social/sessions` → `POST .../messages` → `GET .../messages`；上滑把当前最早一条的 `msgId` 传给 `beforeMsgId`。实时推送没有，文档建议聊天页 **3–5 秒轮询 GET**。
