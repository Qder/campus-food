# 图片上传笔记（campus-food）

> 对照当前代码：上传走 `POST /user/upload`，校验后落本地磁盘，返回 `/uploads/...`；
> 图片再由 Spring MVC 静态资源映射对外提供，不需要经过 Controller。

---

## 1. 一句话流程

```
前端选图
  │  multipart/form-data：file + bizType
  ▼
POST /user/upload（网关 8080 → user-service 8081）
  │  JWT 校验 → UserContext 写入 userId
  ▼
UploadController → UploadService
  │  校验 → 生成路径 → 写磁盘
  ▼
返回 { url: "/uploads/avatar/2026/11/15/xxx.png", size: 12345 }
  │  前端把 url 写进改资料 / 发动态 / 写评价
  ▼
浏览器 GET /uploads/avatar/2026/11/15/xxx.png
  │  网关转发 → user-service 静态资源处理器
  ▼
磁盘文件直接作为响应返回
```

**关键点**：上传是“写”，要走 Controller；读图是“静态资源”，不走 Controller。

---

## 2. 涉及的文件

| 文件 | 职责 |
|---|---|
| `controller/UploadController` | `POST /user/upload`，接收 `file`、`bizType` |
| `service/UploadService` | 接口，只有一个 `upload` 方法 |
| `service/impl/UploadServiceImpl` | 校验、生成路径、写磁盘、返回 URL |
| `vo/UploadVO` | `url` + `size` |
| `config/UploadResourceConfig` | 把 `/uploads/**` 映射到磁盘目录 |
| `campus-food-common` 的 `WebMvcConfig` | JWT 放行 `/uploads/**` |
| `campus-food-common` 的 `GlobalExceptionHandler` | 文件超限转 400 |
| `api-gateway` 的 `application.yml` | `/uploads/**` 路由到 user-service |
| `user-service` 的 `application.yml` | multipart 限制、上传目录 |

## 3. 上传请求怎么进来

### 3.1 网关

`api-gateway/src/main/resources/application.yml`：

```yaml
- id: user-service
  uri: lb://user-service
  predicates:
    - Path=/auth/**,/user/**,/uploads/**
```

`/user/upload` 命中 `/user/**`，转发到 user-service。

### 3.2 JWT 拦截器

`/user/**` 不在放行列表里，所以**上传必须登录**。

```text
// WebMvcConfig
.excludePathPatterns(
        "/auth/register", "/auth/login", "/auth/code",
        ...
        "/uploads/**",   // 只有图片读放行
        "/error"
)
```

### 3.3 multipart 解析

请求头是 `multipart/form-data`，Spring 的 `MultipartResolver` 把每段解析成
`MultipartFile` 或普通字段，所以 Controller 能直接接：

```text
@PostMapping("/upload")
public UploadVO upload(@RequestParam(value = "file", required = false) MultipartFile file,
                       @RequestParam(value = "bizType", required = false) String bizType) {
    return uploadService.upload(file, bizType);
}
```

> `required = false` 是故意的：让“没选文件”走到 Service 里返回中文提示，
> 而不是 Spring 抛一个英文的 400。

## 4. Service 里做了什么

### 4.1 校验顺序

| 顺序 | 检查 | 失败文案 |
|---|---|---|
| 1 | `file == null || file.isEmpty()` | 请选择要上传的图片 |
| 2 | `bizType` 在白名单 | bizType 不合法 |
| 3 | `file.getSize() > 5MB` | 图片不能超过 5MB |
| 4 | 扩展名在白名单 **且** `Content-Type` 以 `image/` 开头 | 只支持 jpg/png/webp/gif 图片 |

白名单：

```text
private static final Set<String> ALLOWED_BIZ_TYPES = Set.of(
        "AVATAR", "REVIEW", "FOOD", "MERCHANT_LOGO", "LICENSE", "FEED", "CHAT");
private static final Set<String> ALLOWED_EXTENSIONS = Set.of("jpg", "jpeg", "png", "webp", "gif");
```

> 扩展名和 Content-Type 都校验，是因为两者都可能被伪造；
> 课设层面够用，生产还应校验文件头（魔数）或重新编码图片。

### 4.2 生成落盘路径

```text
String relativePath = bizType.toLowerCase(Locale.ROOT) + "/"
        + LocalDate.now().format(DateTimeFormatter.ofPattern("yyyy/MM/dd")) + "/"
        + UUID.randomUUID().toString().replace("-", "") + "." + ext;
```

结果形如：

```
avatar/2026/11/15/3f2a9c1d4b7e4c2a8f6d5e1b0a9c8d7e.png
```

三个设计点：

| 设计 | 原因 |
|---|---|
| 业务类型做一级目录 | 头像、评价图、营业执照分开，好清理、好迁移 |
| 年/月/日分级 | 单目录文件过多时文件系统会慢，也方便按天归档 |
| 文件名用 UUID | 不用原始文件名 → 防路径穿越、防重名覆盖、URL 不可猜 |

**绝对不用原始文件名拼路径**：如果用户上传 `../../etc/passwd`，
直接拼路径就会写到目录外。

### 4.3 写磁盘

```text
Path root = Paths.get(uploadDir).toAbsolutePath().normalize();
Path target = root.resolve(relativePath);

try (InputStream in = file.getInputStream()) {
    Files.createDirectories(target.getParent());   // 目录不存在就建
    Files.copy(in, target);                        // 流复制，不用 transferTo
}
```

- `toAbsolutePath().normalize()`：把 `./uploads` 变成绝对路径，消掉 `..`；
- `createDirectories`：按 `yyyy/MM/dd` 一次建多层；
- `Files.copy`：不经过原始文件名，避免 `transferTo` 的路径问题。

### 4.4 返回

```json
{ "url": "/uploads/avatar/2026/11/15/xxx.png", "size": 12345 }
```

`size` 是字节数，前端可用来判断是否为空文件。

## 5. 图片 URL 怎么变成能打开的图片

这一步最容易漏，**三个配置缺一不可**：

| 配置 | 位置 | 少了会怎样 |
|---|---|---|
| 静态资源映射 | `UploadResourceConfig` | 打开 URL 404 |
| JWT 放行 `/uploads/**` | common 的 `WebMvcConfig` | 打开 URL 401 |
| 网关路由 `/uploads/**` | gateway 的 `application.yml` | 经 8080 打开 404 |

### 5.1 静态资源映射

```text
String location = Paths.get(uploadDir).toAbsolutePath().normalize().toUri().toString();
if (!location.endsWith("/")) {
    location = location + "/";
}
registry.addResourceHandler("/uploads/**").addResourceLocations(location);
```

生成的是 `file:///E:/.../uploads/` 这种 URI。

> location **必须以 `/` 结尾**：Spring 把它当目录前缀拼文件名，少了斜杠会拼成
> `uploadsavatar/...`，结果 404。

### 5.2 为什么图片读要放行 JWT

浏览器 `<img src="/uploads/...">` **不会带 `Authorization` 头**。
如果拦截器不放行，图片全是 401、页面全裂。

所以图片是“靠 UUID 不可猜”来保护的，不是靠 Token。这也意味着：
**不要用它存敏感文件**。`LICENSE`（营业执照）属于敏感图，生产应换成私有存储 + 鉴权下载。

## 6. 为什么 5MB 要配两处

| 层 | 配置/代码 | 作用 |
|---|---|---|
| Tomcat / Servlet | `spring.servlet.multipart.max-file-size: 5MB` | 请求还没进 Controller 就拦下，防止把大文件读进内存 |
| 业务代码 | `file.getSize() > MAX_FILE_SIZE` | 兜底，防止配置被改或测试环境不同 |

配套两个参数：

```yaml
spring:
  servlet:
    multipart:
      max-file-size: 5MB       # 单个文件
      max-request-size: 6MB    # 整个请求（multipart 有 boundary 等额外开销）
server:
  tomcat:
    max-swallow-size: -1       # 超限时把请求体读完再返回 400，避免客户端看到连接重置
```

超限时抛 `MaxUploadSizeExceededException`，由 `GlobalExceptionHandler` 转成：

```json
{ "code": 400, "message": "图片不能超过 5MB" }
```

## 7. 磁盘目录长什么样

```
uploads/
├── avatar/
│   └── 2026/11/15/3f2a....png
├── review/
│   └── 2026/11/15/8b1c....jpg
└── license/
    └── 2026/11/15/c7d9....png
```

**目录位置取决于启动时的工作目录**：

- IDEA 直接运行：默认是模块目录，可能是 `user-service/uploads`；
- `java -jar`：执行命令时所在的目录；
- 想固定位置，就在 yml 里写绝对路径：`app.upload.dir: E:/campus-food/uploads`。

建议把 `uploads/` 加进 `.gitignore`（目前还没加），否则 `git status` 会冒出一堆图片。

## 8. 常见问题排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 401 未登录 | 上传接口要 Token | Header 加 `Authorization: Bearer <token>` |
| 400 bizType 不合法 | 大小写不对 | 必须大写：`AVATAR` |
| 400 请选择要上传的图片 | multipart 字段名不是 `file` | 表单字段名改成 `file` |
| 400 只支持 jpg/png/webp/gif | 扩展名或 Content-Type 不符 | 换图片，别改后缀名 |
| 400 图片不能超过 5MB | 超过限制 | 压缩后再传 |
| 上传 200，打开 404 | 缺静态映射或网关路由 | 对照第 5 节三处 |
| 上传 200，打开 401 | 没放行 `/uploads/**` | 加进 excludePathPatterns |
| 换电脑图片全没了 | 文件在本地磁盘 | 迁移目录，或改 OSS/MinIO |
| `git status` 出现 uploads | 没忽略 | `.gitignore` 加 `uploads/` |

## 9. 和 3.9 评价带图的关系

```
1) POST /user/upload（bizType=REVIEW）→ 拿到 url
2) POST /food/{id}/reviews，body 里带 images: ["/uploads/review/..."]
```

上传接口只负责“把文件存好、给出 URL”，不关心业务；
评价、动态、头像都复用它，各自把 URL 写进自己的表。

---

## 10. 已知限制

1. **本地磁盘**：换机器、清目录就丢，答辩前别清理 `uploads/`；
2. **图片公开可访问**：靠 UUID 不可猜，不适合营业执照等敏感文件；
3. **没有压缩/缩略图**：原图直出，大图会拖慢列表页；
4. **没有频率限制**：同一用户可以反复上传刷盘，生产要加配额或限流；
5. **写盘失败可能留半截文件**：可以在 `catch` 里 `Files.deleteIfExists(target)` 清理。
